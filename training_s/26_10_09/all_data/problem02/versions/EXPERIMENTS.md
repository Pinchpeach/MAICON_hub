# problem02 (드론 비행 상태, Macro F1) 실험 기록
검증: 비행(uid) 단위 Leave-One-Flight-Out 5폴드 OOF (비행 5개, DESCEND 구간 31개뿐이라 변동 큼). 사용자 목표: 정확도 95% 이상.

| 구성 | 정확도 | Macro F1 | ASC | DESC |
|---|---|---|---|---|
| 평탄 RF 34특징 | - | 0.690 | 0.463 | 0.349 |
| 평탄 HGB 34특징 | - | 0.701 | 0.493 | 0.417 |
| 계층 A (ASC+DESC 묶음→2단계) RF | 0.839 | 0.687~0.704 | 0.46~0.50 | 0.34~0.39 |
| 계층 B (DESCEND 전용 먼저) RF | - | 0.685 (임계 0.7: 0.651) | 0.449 | 0.342 |
| +원값 센서(전압·전류·바람) | - | 0.638~0.659 | - | 0.18~0.26 → 제외 |
| v2 특징 59개 A-RF | 0.835 | 0.732 | 0.727 | 0.323 |
| v2 A RF+HGB 확률평균 | 0.840 | 0.736 | 0.704 | 0.356 |
| + 과거 지수평활 α=0.5/0.8/0.9 | 0.836/0.800/0.756 | 0.727/0.677/0.615 | - | - → 제외 |
| **v2 + ASC x3, DESC x5 가중 (메인 v2)** | **0.840** | **0.782** (낙관적) | 0.794 | 0.497 |

- 메인: `v2_featx_ens_wt_main.csv` = `submission.csv` (10,499행, id,flight_state). 노트북 `work.ipynb` Restart & Run All 로 출력 저장, 원본은 `notebook_orig.ipynb`. 실험 스크립트는 `scripts/`.
- **가중치는 OOF 점수로 골라 낙관적.** 가중 없음은 Macro F1 0.736.
- **95% 정확도 미달성(0.84).** 오류의 55%가 상태 전환 경계 5행 이내(경계 근처 정확도 0.63), 구간의 63%가 1~2행짜리라 센서만으로는 맞히기 어려움. 경계 5행 이내 오류를 모두 제거해도 가상 정확도 0.926. 큰 오류: IDLE↔HMSL 약 4,200행, ASC/DESC→IDLE 약 1,500행.
- 테스트 예측 분포: IDLE 52.6%, HMSL 29.6%, TURN 13.0%, ASC 3.4%, DESC 1.5% (train: 54.4/29.8/9.6/2.9/3.3). 테스트 비행이 train과 센서 분포가 달라 TURN 비중 차이는 비행 조건일 수 있음(미확인).
- 미시도: IDLE↔HMSL 개선용 긴 구간·주파수 특징.

- [호환 수정 반영] HGB 2단계의 class_weight="balanced"(sklearn 1.2+ 전용)를 sample_weight 로 교체. 예측 100% 동일, 점수 동일.
- stack 실험(RF+HGB stack1, HGB 메타): 가중 없음 기준 정확도 0.851 / Macro F1 0.775 (앙상블 0.840 / 0.736), 낙관적 가중 시 0.786 vs 0.782로 거의 같음. stack1 생성 1,186초(개발 PC)라 서버 2코어 25~40분(추정) → 비용 때문에 미채택. 스크립트 scripts/cv_stack.py, scripts/stack2.py.
- [중단] stack1 을 HGB 만으로 줄인 재시험은 비행 1개에 233초(RF+HGB 270초)로 절감이 거의 없어 09:55 에 중단. 메인은 앙상블 유지.
